# POINTS 联网版实施方案

## 目标
将当前本地单设备积分应用升级为 Android、iOS 和浏览器可共同访问的多人实时积分管理系统。当前文件仅为技术方案，不代表云端服务已经开通。

## 联网版必须具备
- 用户注册/登录与会话管理
- 团队创建、邀请成员加入
- 服务端角色权限：团队所有者、管理员、只读成员
- 多设备实时同步成员、积分、排行榜和流水
- 服务端校验积分上限、禁止负积分、撤销操作
- 服务端审计日志，记录操作者、时间、目标成员和变更前后值
- HTTPS、数据库访问策略、备份与恢复

## 建议的数据模型
- `profiles`: 用户资料
- `teams`: 团队名称、创建者、创建时间
- `team_memberships`: 用户与团队关系、角色、加入时间
- `members`: 团队内被计分对象、分组、头像颜色、当前积分
- `point_transactions`: 每笔加分/扣分、操作者、备注、时间、撤销关联
- `audit_logs`: 管理操作事件及操作者

所有业务记录必须带 `team_id`。成员积分变化与流水写入应在同一数据库事务中完成，避免分数与流水不一致。

## 权限规则
- Owner：管理团队、成员、管理员和全部积分数据
- Admin：管理成员、调整积分、查看流水
- Viewer：只能查看成员、排行榜和流水
- 权限必须在服务端/数据库策略中验证，不能只依靠网页隐藏按钮或本地 PIN。

## 迁移策略
1. 用户登录并创建或加入团队。
2. 从当前设备导入 POINTS JSON 备份。
3. 服务端验证字段、积分范围、成员关系和重复数据。
4. 在一个事务中写入团队、成员、积分流水和可迁移的操作记录。
5. 对比导入前后成员数量、总积分和流水数量。
6. 验证通过后切换为云端数据源；保留 JSON 导出作为应急备份。

## 当前状态与下一阶段
- 当前应用仍使用浏览器 `localStorage`，不同设备不会自动同步。
- `display.html` 是同一设备/浏览器数据的只读展示页，不是公开云端看板。
- 尚未配置云数据库、身份认证、实时通道或服务器端权限。
- 下一阶段先确定可访问的后端服务，再建立数据库结构与访问策略，随后接入登录、团队邀请和实时同步。
- 不要把管理员 PIN 摘要当作联网版身份认证；联网后由服务端角色权限取代本地 PIN。

## 已选云端方案：Appwrite Cloud

本项目联网后端优先采用 Appwrite Cloud，原因是它在一个项目中提供身份认证、数据库、实时订阅和云函数，并支持从 Git 部署前端。免费计划适合开发与小规模试用，但有资源配额；达到配额时，API、实时订阅、注册/邀请等能力可能暂时受限。上线前必须在控制台检查实际配额和使用量。

### POINTS 的 Appwrite 接入设计

- 前端：保留现有响应式网页/PWA 和黑白 UI，不重写成原生 App。
- 登录：Appwrite Auth 邮箱注册、登录、退出和会话恢复。
- 数据：以 `teams`、`team_memberships`、`members`、`point_transactions`、`audit_logs` 为核心表。
- 实时：订阅当前团队相关数据变化，成员积分、排行榜和流水同步刷新。
- 权限：所有表启用权限控制；每个团队的数据只允许该团队成员访问。Owner/Admin/Viewer 权限由后端校验，不能依赖前端隐藏按钮。
- 积分操作：优先通过受控云函数执行加分、扣分、批量调整和撤销，确保积分与流水一致，防止客户端直接篡改。
- 迁移：保留现有 JSON 导入/导出；登录后由用户主动把本机数据迁移到团队云端。

### 接入边界

Appwrite 项目必须由项目所有者账号创建。POINTS 代码会提供连接配置入口，但 Appwrite Endpoint、Project ID 等公开配置需要由项目所有者填入；任何 API Secret 或服务端密钥都不得放进网页代码或 Git 仓库。正式启用前需要在 Appwrite 控制台完成一次平台注册/项目授权和允许的 Web 平台域名设置。

## 上线验收
- 两台不同设备登录同一团队后能看到相同数据。
- 一台设备加分后，另一台设备实时更新。
- Viewer 无法通过直接调用接口修改数据。
- 非团队成员无法读取团队数据。
- 并发调整积分不会覆盖或丢失流水。
- JSON 导入、导出和恢复经过验证。
